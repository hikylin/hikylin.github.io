可信工程能力提升

本文转载于–原hvv的一位前辈。希望可以帮助到你我。

开始之前

我想先提出一个红车问题：今天上班路上，你看到红色的车了吗？

答案可能是否定的，但是事实每天你都可能见到了红色的车。而当你决定买一辆红色的车时候，你会发现怎么到处都是红色的车。心理学有很多相关的理论是解释这个现象。核心观点就是：人们会不自觉的关注自己在意的事情，并因此更容易在周围环境中发现与之相关的信息或机会。

如果我们把红车看成目标或者机会，当你明确自己的目标并主动关注的时候，显然可以更容易发现他们。

因此说到面试，我很喜欢看机会这个词，如果你关注机会，那么你也许很快就找到了机会，所以本文看到这里，核心内容就已经说完了。

面试

其实我的面试历程比较简单，25 年开始的时候就慢慢看机会，我在投简历之前观察了一下市场，专门看了下现在前面开的包比较大的岗位是要做什么的，与我工作的相关度，然后针对性的修改简历进行面试。先找了一堆小公司面试，后面慢慢是一些大厂和外企，最后再有offer横向比较。

虽然说AI出现，各种公司陷入抢人才大战，和AI相关的岗位开的薪资很高，是存在一定的泡沫的。但我认为对于普通人来说泡沫是好事，也是难得的机会，没有资本的注入哪来的泡沫。而且AI兴起也就这么两年，既然以前所谓的专家摇身一变也能变成AI专家，咱们普通人也不要妄自菲薄，能来华子的学习能力都是没有问题的，脑子也不比谁差，认真学一学也能做泡沫中喝口汤。

去年大概面了 20 来家大小公司，认真准备的也就 10 家左右，下面是我在常规的面试流程中分点交流一下自己的理解，给各位一些参考。

在流程之前，我想补充一下我觉得面试之外的点，那就是：要深刻关注你的目标。

  • 对于招聘方来说，别人是找一个一起共事，一起工作的同事

面试一般都是视频面试，因此你的所有输入信息，你的外貌、声音、表情，写代码的节奏都会是影响面试结果的参数。

所以你必须先调整好的摄像头，调整光线，面试时候保持一个干净、舒适的形象，让别人觉得和你做同事是舒服的。人生的一大捷径可能就是打扮好自己。“言语压君子，衣冠镇小人”，几乎没有人能摆脱以貌取人的刻板印象，大部分人无法免俗。

  • 对于面试的形式来说，本质就是聊天和写代码

面试考察的内容有限，你要练习聊天能力，同样的文字内容，是带着一堆语气词，吞吞吐吐的说出来，还是流程清晰的中气十足的表达出来，结果是显然不同的。想象你要和心仪的女孩进行第一次约会，如此重要的场合，私下里一定会把：呼气、微笑、声线、语气、停顿，都刻意练习。

  • 如果没有明确说不允许录音，那就电脑开外放，手机录你的面试

面试完复盘是学习成长最快的时候。平时我不想学，不想看的东西，别人一问，我就很有动力搞懂，因为当时没有回答出来的难受会让我记忆很久。所以有每次面试的录音，帮助自己复盘回答是很有必要的。我的方法是：每次面试完觉得自己回答不好的问题，和没有回答上来的问题，搞懂后，自己录音一遍回答，说到自己听着满意为止。

简历

简历改了大约一个月，中间还请了OpenAI的朋友帮我修改了一版。简历中的项目我是按他推荐统一如下格式写的：

  • 项目名：名字后跟自己的角色
  • 技术架构：一行说明
  • 项目描述：说清楚项目背景
  • 责任描述：3-4 点关键的工作
  • 技术描述：3-4 点核心的技术点

大概三个项目就能写一页，加上个人信息，教育经历，相关的技能，简历总共写了两页半。

投简历的时候，按照过来人的建议，针对不同的jd会对项目进行一下调整，调整目标就是增加你的项目和对方jd的匹配度，我觉得这个细节很重要，因为本来是OD面试机会不多，按照这个简历的调整后我只遇到一次简历挂的场景。

自我介绍

这个过程没啥特别的，也没有什么特定模板。但是我多次面试体验下来一个技巧就是：根据面的岗位你的匹配程度，合理分配说的每个项目的时间：比如对于没有太多把握的面试，我习惯开始先把自己熟悉的项目多说一些，这样可以杀一些时间。对于自己熟悉的技术，可以在结束时候特地点一下，主动引导面试官往自己擅长的方向去说，有效增加前面技术面通过的概率。

项目技术

最基本的，需要把简历上的每个缩写，每个技术都搞清楚，否则被问到答不出来就很尴尬，那大概率这场面试也会挂。

每个面试官问的问题没有什么规律可言，问题形式可能不同，但是本质主要是围绕以下几个问题的回答流程：

  • 项目中的挑战点，难点，怎么解决，解决后对你的成长
  • 对一些技术的思考理解，方案选型怎么做trade-off
  • 项目合作的方式，团队组成，项目周期的理解
  • 对新技术的洞察

这些问题比较大，我的简历上咩个项目，我都针对的整理了这类大问题的回答话术，所以在被提问的时候，每个问题我都能从三个项目里套出一套输出。因为每个面试官的技术树可能不同，关注的具体项目也不太一样，只好全部准备出来，能应付前面的技术面试才有后续。

这块我无法给出我的项目的学习材料。技术相关很多经典书籍材料不做赘述，但是有一些公开的材料我认为值得一读。有拿来即用的观点，面试的时候随便旁征博引几句作为自己的思考，还是能让面试官眼前一亮的（我面试回答的时候会留意面试官的表情）。

  • 关于软件工程：构建之法（第三版）作者邹欣
  • 关于设计模式：游戏编程模式
  • 关于MLSys：CMU 10-714，CMU 15-779
  • 关于C++：https://github.com/Cpp-Club/Cxx_HOPL4_zh
  • 关于新技术：利用好公司的稼先社区，有的写的好的洞察，我会反复看到几乎全文背诵的程度

Coding

由于自己是高考保送的竞赛选手，加上社招不会考太高级的算法，所以Coding环节还是比较轻松的，我个人关注的一些细节分享一下：

  • 代码不要写太快，也不能写太慢

轻松经历，写太快面试官会觉得你在背题，可能再给你加一道题，所以无论你觉得多么简单，控制 20 分钟左右写完。

  • 写之前和面试官保持沟通

问清楚问题的细节，比如数据规模，一些隐含的条件确认，简单讲讲你的思路，如果面试官肯定你的思路，那么这个题当然就完成一半了。

  • 记得补充测试用例

写完以后，增加一下边界用例，和基础测试用例，既方便自己调试，也能体现你的工程思维

  • 尽量把时空复杂度写成最优
  • 加上一下最优性的剪枝，空间的优化，细节的处理，这里是最能拉开差距的地方。这块说起来比较抽象，我给出几个常见的面试力扣算法题：
  • 无重复字符的最长子串
class Solution {
public:
    int lengthOfLongestSubstring(string s) {
        int left = 0;
        int max_len = 0;
        unordered_set<char> window;
        for (int right = 0; right < s.length(); right++) {
            while (window.find(s[right]) != window.end()) {
                window.erase(s[left]);
                left++;
            }
            window.insert(s[right]);
            max_len = max(max_len, right - left + 1);
        }
        return max_len;
    }

    /* vector 每个字符出现的频率 */
    int lengthOfLongestSubstringVecFreq(string s) {
        vector<int> freq(128, 0);
        int max_len = 0;
        int left = 0;
        for (int right = 0; right < s.length(); right++) {
            freq[s[right]]++;
            while (freq[s[right]] > 1) {
                freq[s[left]]--;
                left++;
            }

            max_len = max(max_len, right - left + 1);
        }
        return max_len;
    }
  	/* 原文提到的方法 */
  	int lengthOfLongsetSubstringVecPos(string s) {
        vector<int> pos(128, -1);
        int n = s.size(), start = -1, ans = 0;
        for (int i = 0; i < n; i++) {
            start = max(start, pos[s[i]]);
            ans = max(ans, i - start);
            pos[s[i]] = i;
        }
        return ans;
    }
};

本题的常规写法是滑动窗口，但是我认为其实更好的写法是维护字符上个出现位置。虽然时空复杂度一致，但是vector更新的效率会更高，减少了hash容器的维护成本，如果用这个写法，记得讲出你的写法的优势，会留下一个比较好的印象。

  • 最长回文子串
//最长回文子串
class Solution {
public:
    string longestPalindrome(string s) {
        int n = s.size();

        if (n < 2)return s;
        int i = 0;
        int start = 0;
        int maxLen = 1;
        while (i < n) {
            int left = i;
            int right = i;

            if (n - i <= maxLen / 2) {	//剪枝 1
                break;
            }
            while (right < n - 1 && s[right] == s[right + 1])right++; //剪枝 2

            i = right + 1;

            while (left >= 0 && right < n && s[left] == s[right]) {
                left--;
                right++;
            }

            int len = right - left - 1;

            if (len > maxLen) {
                start = left + 1;
                maxLen = len;
            }
        }
        return s.substr(start, maxLen);
    }
};

本题最好的解法是马拉车算法（Manacher），时间复杂度可以做到O(n)O(n)，但是没有特别准备过一般人很难一把写出来，刚开始面试的时候出了这道题，调试半天写出来后感觉没有啥收益。感觉面试官出这道题最想看到的还是原始的O(n^2^)，该算法有好多种写法，时空复杂度最优的题解区都有，但是都还不够好。后续面试再遇到这个题，我掏出这个剪枝后，明显面试官是比较兴奋的，后面我测了下力扣上数据只用剪枝 2 是用时就不输马拉车算法了。

  • LRU缓存
struct Node {
    int key, value;
    Node *prev;
    Node *next;

    Node(int k, int v) : key(k), value(v), prev(nullptr), next(nullptr) {
    }
};

class LRUCache {
private:
    int capacity;
    unordered_map<int, Node *> cache;
    Node *head;
    Node *tail;

    void addToHead(Node *node) {
        node->next = head->next;
        head->next->prev = node;
        head->next = node;
        node->prev = head;
    }

    void removeNode(Node *node) {
        node->prev->next = node->next;
        node->next->prev = node->prev;
    }

    void moveToHead(Node *node) {
        removeNode(node);
        addToHead(node);
    }

    Node *removeTail() {
        Node *rmNode = tail->prev;
        removeNode(rmNode);
        return rmNode;
    }

public:
    LRUCache(int capacity) : capacity(capacity) {
        head = new Node(0, 0);
        tail = new Node(0, 0);
        head->next = tail;
        tail->prev = head;
    }

    int get(int key) {
        auto it=cache.find(key);
        if (it != cache.end()) {
            moveToHead(it->second);
            return it->second->value;
        } else {
            return -1;
        }
    }

    void put(int key, int value) {
        auto it=cache.find(key);
        if (it != cache.end()) {
            it->second->value = value;
            moveToHead(it->second);
        } else {
            Node *node = new Node(key, value);
            addToHead(node);
            // cache[key] = node;
            cache.emplace(key, node);
            if (cache.size() > capacity) {
                Node *delNode = removeTail();
                cache.erase(delNode->key);
                delete delNode;
            }
        }
    }

    ~LRUCache() {
        Node *current = head;
        while (current != nullptr) {
            Node *next = current->next;
            delete current;
            current = next;
        }
    }
};

本题题解区的所有解法都没有写析构函数，但是熟悉C++的朋友都知道，C++的对象生命周期管理是个复杂的话题，没有处理好将是灾难，所以作为常见的面试题，能写对逻辑出来结果很容易。我记得面试给这个题的时候我写完析构函数，阿里面试官说，我是他面试以来唯一一个考虑到写析构的人。我想这个细节肯定有不少加分的。

限于篇幅还有很多常见的算法题就不一一介绍了。因此注意刷题的时候不要仅仅追求通过，要追求最优的实现，这些袭击也是很体现你的Coding能力的地方。很多题解区的算法也不是最优的，做完后要深度思考一下，有没有更好的实现，尤其是常见的面试算法题。

另外面试一般都是共享屏幕白板的网页写，有的是自带语法提示，有的就相当于是一个Notepad，有的小公司会让你在本地的ide写但是要求关闭AI提示。因此要习惯白板写代码。对于C++记住常见的标准库，成员函数，刷题的时候要控制时间，补充测试用例和边界，个人体感就是直接写完一个bug free的代码也意味着这次面试通过了。

反问

我认为反问是一个非常能加分的环节，一开始我对这个环节非常随意，后来面试发现如果能提出好的针对该公司的问题，会大大增加面试官对你的兴趣。

一般我准备的反问就是：

  • 公司在某块技术的选型方向。
  • 当前业务的技术难点在xxx，还是xxx
  • 面试官眼里认为优秀的人才，具备什么特质。

这样可以了解公司的一些技术方向，企业文化，选人的风格，给后续的面试增加一些准备。

谈薪

谈薪没什么特别的技巧，想最大化利益，本质要像渣男一样，每个offer都表示是自己最爱的那个。拿到offer后可以用来argue其他的offer。前期的offer尽量追求高的定级，用来谈其他offer时候议价空间会很高。除此之外，HR也会横向对比候选人，所以多准备几个offer用来体现你的竞争力。

心态

准备面试的时候和曾经一起比赛认识的学生时代的好友交流，如今再接触竟觉十分感慨。发现有人已经基本财富自由，有的人润去了喜欢的地方过上了想要的生活，还有些是职业发展不错在大厂已经身居高位。可能我们之前相处还算愉快，给了我很多好的见解和指导，由是感激。所以总结下来，上山时要谦虚坦诚，尽可能的帮助朋友，因为下山的时候还要碰见，你我或许曾经取得过一些成绩，可是下一次机会，说不定是曾经哪位朋友做的更好。如今，别人把你当回事的时候，千万别太认真，一声大佬或者老师，是对你曾经努力的尊重；不把你当回事的时候也别生气，风水轮流转，只要不下牌桌，总有机会。

诗酒趁年华

工作本身也只是进入地球online的支线任务，如果目标是赚钱，靠单纯工作积累大量财富是很难的，在别人的定价系统里被动追逐，没有生产资料，永远循环在靠时间换钱的框架里。

对于我这种普通人来说，能有的选择不多。最后看了一圈下来外面任然是存在work life balance的机会的，于我而言拥有双休和更多的假期，意味着更丰富的生活，远比多的那点薪水更有价值。

所以再回过头来看，面试只是人生的小插曲，面完后也只是换个地方工作而已。如果当前做的不开心就要付出改变的勇气，不要麻木在每日的上下班打卡中。要记得每天留点时间思考自己。

结语

“风月平生意，江湖自在身。”
